# BrainGram Android — классическая тема

## Принятое решение

Пользователь выбрал классическое оформление Telegram для Android. BrainGram должен сохранить привычную структуру и плотность интерфейса Android-клиента Telegram, но иметь собственное имя, значок и идентичность.

## Визуальные правила для первого этапа

- Основная поверхность: светлая, близкая к белой.
- Верхняя панель и активные элементы: классический голубой акцент.
- Основной текст: тёмный, вторичный текст: серый.
- Список диалогов: аватар слева, имя и последнее сообщение в центре, время и счётчик непрочитанного справа.
- Нижняя/плавающая кнопка нового сообщения — голубая, круглая.
- Экран переписки: привычная шапка с кнопкой назад, аватаром, именем и статусом; сообщения разделены по отправителю.
- Настройки и профиль должны использовать стандартные Android-паттерны исходного клиента, а не веб-панель из текущего React-прототипа.

## Цветовые токены BrainGram

Это стартовые токены брендинга, а не утверждение о точных внутренних значениях цветов Telegram:

| Назначение | Значение |
|---|---|
| Акцент | `#3390EC` |
| Фон приложения | `#FFFFFF` |
| Основной текст | `#222222` |
| Вторичный текст | `#707579` |
| Разделители | `#E7E9EB` |
| Светлая заливка акцента | `#EAF3FC` |

При интеграции нужно сверить компоненты с актуальным upstream UI и избегать глобальной замены цветов, которая может испортить состояния, контрастность или темы.

## Первый экран (список чатов)

Обязательные состояния:

1. Загрузка: индикатор и skeleton-строки.
2. Пустой список: понятное сообщение и действие «Новое сообщение».
3. Ошибка сети: ненавязчивое сообщение и повторная загрузка.
4. Список: аватар, отображаемое имя, превью последнего сообщения, время, непрочитанное.
5. Поиск: фильтрация/поиск диалогов без потери позиции списка.

## Граница первого релиза

Визуальный порт не должен выдавать Telegram-сервисы за BrainGram. Пока не реализован собственный адаптер авторизации, пользователей, переписок, вложений и push-уведомлений к backend BrainGram, экран не считается рабочим мессенджером.

## Следующий технический шаг

Получить полный upstream-репозиторий с submodules и зафиксировать конкретный commit в отдельном Android-проекте/ветке. После этого определить минимальный экранный срез для переоформления, проверить applicationId, модули сборки и зависимости. Только затем менять код интерфейса и подключать backend.
